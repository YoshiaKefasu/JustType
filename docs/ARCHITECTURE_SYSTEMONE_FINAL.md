## 1. アーキテクチャの基本哲学（コアコンセプト）

1. **生成型（Generative）から判断型（Decision）への完全移行**
   - 1文字ずつ文字を捏造・生成する方式を全廃し、**「網羅的な選択肢の中から文脈に一番合うものを 1 つ選ぶ」** 構造に一本化する。
   - 変な文字や記号を捏造する事故（ハルシネーション）を**数学的・原理的に 100% ゼロ**にする。
2. **KISS 原則（直交分離）**
   - **英語の保護**は「Meltype」に任せる（漢字エンジンを通さない）。
   - **日本語の候補出し**は「Mozc の最強辞書」に任せる。
   - **文脈判定とタイポ救済**は「システムOne（決定モデル）」に任せる。
   - それぞれの役割を絶対に混ぜず、クリーンに直交させる。
3. **キー入力 0ms 即応（完全非同期）**
   - タイピングの打鍵処理に同期的な推論や通信を一切挟まない。
   - 画面は常に 0ms で滑らかに動き、AI の回答は裏のバックグラウンドワーカーから非同期に届いて候補をアップグレードする。

## 3. レイヤー別 詳細仕様

### 【Layer 1】Meltype スライス層（英日直交分離）
- **役割**: 入力ローマ字（`raw`）を、意味のある最小単位のピース（チャンク）に切り分ける。
- **処理仕様**:
  1. 入力されたローマ字を Meltype 辞書（72万語日本語＋英単語）で解析。
  2. 英語と判定された部分（`google`, `zenz`, `facebook`, `reddit` 等）は **`is_english = true`** としてマーク。
  3. **英語ピースは Mozc 変換エンジンに一切渡さない**。最初から `key = raw, value = raw` として隔離し、後ろの助詞（「で」「に」）による巻き込み誤変換（「後おgぇで」等）を原理的に根絶する。
  4. 辞書から日本語ローマ字と衝突する単語（`ann`, `inn`, `unn`, `sade` 等）は完全排除済み。
  5. 末尾 `s` の横取り防止ルールにより、`discordsa-ba` は `discord` ＋ `sa-ba`（サーバ）に綺麗に分離される。

---

### 【Layer 2】ピース別 2PASS 決定パイプライン

#### ■ PASS 1: 音素・タイポ・未完成解決（Phoneme Resolution）
ユーザーがタイポした時、あるいは打鍵途中で手が止まった時に、**決定モデル（Jev / Laya）に「日本語の音」を補正・補完させる**ステップ。

- **渡す選択肢（日本語音素フルセット: 計107音）**:
  生成モデルを使わず、以下の **閉じた選択肢リスト** から選ばせる。
  ```text
  ・直音（五十音）:
    あ い う え お
    か き く け こ
    さ し す せ そ
    た ち つ て と
    な に ぬ ね の
    は ひ ふ へ ほ
    ま み む め も
    や     ゆ     よ
    ら り る れ ろ
    わ             を
    ん

  ・濁音:
    が ぎ ぐ げ ご
    ざ じ ず ぜ ぞ
    だ ぢ づ で ど
    ば び ぶ べ ぼ

  ・半濁音:
    ぱ ぴ ぷ ぺ ぽ

  ・拗音・促音:
    きゃ きゅ きょ
    しゃ しゅ しょ
    ちゃ ちゅ ちょ
    にゃ にゅ にょ
    ひゃ ひゅ ひょ
    みゃ みゅ みょ
    りゃ りゅ りょ
    ぎゃ ぎゅ ぎょ
    じゃ じゅ じょ
    ぢゃ ぢゅ ぢょ
    びゃ びゅ びょ
    ぴゃ ぴゅ ぴょ
    っ

  ・長音記号:
    ー
  ```

- **判定の挙動**:
  - **未完成（打ちかけ）の時**:
    - 文脈: `ある程度の`
    - 打ちかけ: `naga`（なが）
    - 音素選択: 選択肢から `さ`（長さ）や `い`（長い）が選ばれ、単語の完成形を先回り予測。
  - **タイポの時**:
    - 入力: `おたれさま`（`otaresama`）
    - 文脈: `いつも`
    - 音素選択: `た` の位置に対して、選択肢から文脈適合度最高の **`つ`** が選ばれ、本来の読み `おつかれさま` が復元される。

#### ■ PASS 2: 形態素・文脈漢字選択（Surface Selection）
復元された読みと辞書候補をガッチャンコして、最終的な漢字表記を決定するステップ。

- **左文脈（Left Context）の自動結合**:
  直前のピース群の確定文字列をそのまま左文脈として渡す（例: `さっき google `）。
- **完全網羅された選択肢（Options）の構築**:
  Jev / Laya に渡す選択肢リストは、以下の順序で自動生成される：
  - **A. かなそのまま**: 未確定・無変換（まだ打ってる途中のためのエスケープハッチ）
  - **B. タイポ救済表記**: PASS 1 で補正された読みから引いた候補（例: `お疲れ様`, `ダメでした`）
  - **C. ローマ字そのまま**: 英字入力（例: `google`, `facebook`）
  - **D〜Z. Mozc 辞書候補 ＋ ユーザー学習履歴候補**: 通常の変換候補（例: `調べた`, `しらべた`）
- **判定結果の反映**:
  - Jev / Laya が選んだ `choice` を、該当ピースのセグメントの `value` として採用する。

---

### 【Layer 3】プレゼンテーション ＆ コミット層
- **0ms ベースライン即時表示**:
  キー入力が行われた瞬間は、Mozc のデフォルト辞書候補（第1候補）を 0ms で画面に出す。これにより、タイピング時の引っ掛かり（ラグ）は完全にゼロ。
- **インプレース非同期更新**:
  裏のワーカーから Jev の判定が返ってきたら、該当ピースの文字だけをシュッと最新の漢字に置き換える。
- **Enter 確定（Commit）**:
  Enter が押されたら、各ピースの文字列を「英日境界ルール（英語に触れる境界のみ半角スペースを挟む）」に従って合体し、OS へ直接コミットする。
  👉 **`さっき google で調べた`**

## 4. トレードオフの克服と安全対策（ガード設計）

| 潜在リスク | 本アーキテクチャでの解決策 |
| :--- | :--- |
| **パタパタ点滅（チラつき）** | 入力中は Mozc ベースラインを静かに維持し、手が止まった瞬間（デバウンス 200ms）または文節確定時に 1 回だけ更新する設計で点滅を排除。 |
| **AI の過補正（余計なお世話）** | 選択肢 A に必ず「かなそのまま」「打ったローマ字そのまま」を常に常駐させ、造語や略語の時は AI に「A（触るな）」を選ばせる。 |
| **外部 API のレート制限（429）** | SystemOne が 429 エラーやタイムアウト（上限 500ms）になった場合は、即座に Mozc デフォルト辞書変換へフォールバックし、タイピングを絶対に止めない。 |
| **将来の完全ローカル化** | 本構造は入力と選択肢がすべてテキストで閉じているため、RTX Blackwell 上に `laya-multilingual`（GGUF / TensorRT）を常駐させれば、通信遅延 0ms・完全オフラインで同一パイプラインがそのまま爆速稼働する。 |
